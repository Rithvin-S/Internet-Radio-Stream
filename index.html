Icecast Integration & System Architecture

1. Icecast 2.4+ Setup Architecture

In accordance with Section 3 of the SRS, the extended release connects a broadcasting source to an Icecast server to distribute a live MP3/AAC audio stream to multiple browser clients simultaneously. 

[ Broadcast Source: OBS / BUTT / Mixxx ]
                 ↓ (source protocol port 8000)
    [ Icecast 2.4 Streaming Server ]
                 ↓ (HTTP/HTTPS mount e.g. /live.mp3)
  [ Modern Web Browsers (HTML5 Audio Player) ]

2. Broadcaster Software Configuration (OBS / BUTT / Mixxx)

  • Server Type: Icecast 2
  • Server Address: 127.0.0.1 (or your public server IP / domain)
  • Port: 8000
  • Mount: /live.mp3
  • Password: Configured <source-password> in icecast.xml
  • Audio Codec: MP3 (128 kbps or 192 kbps, 44.1 kHz, Stereo)

3. Multi-Listener Verification (TC-12)

To test the multi-listener requirement from FR-12 and TC-12:

  1. Start Icecast and begin broadcasting audio from your source software.
  2. Ensure firewall allows inbound TCP on port 8000 (or HTTPS reverse proxy 443).
  3. Enter your stream URL (e.g., http://<your-ip>:8000/live.mp3) into the Custom Stream box above.
  4. Open the player on Device 1 (e.g. desktop) and Device 2 (e.g. smartphone or secondary browser).
  5. Verify that both listeners can simultaneously hear the broadcast without interference.

4. HTTPS & Mixed-Content Note (NFR-08, TC-11)

Browsers block HTTP streams when the host website is served over HTTPS (Mixed Content restriction). When deploying to production on HTTPS (GitHub Pages, Vercel, Netlify), your Icecast server should use an HTTPS reverse proxy (e.g. Nginx with Let's Encrypt SSL certificate) or use an authorized HTTPS stream URL.
